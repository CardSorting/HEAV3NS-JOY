# HEAV3NS-JOY: アーキテクチャ主権と構造エントロピー制御フレームワーク

[English](../../README.md) · [他の言語](README.md) · [入門ガイド](../GETTING_STARTED.md) · [Agent プロトコル](../../AGENTS.md)

> *「エージェントを実行するだけの場所をこれ以上作るな。エージェントが学び、持ち帰り、どこでも独立して再現できるものを構築せよ。」*

**一行要約:** HEAV3NS-JOY は、極小の規約と依存関係ゼロの監査ツールにより、人間および AI コーディングエージェントによるコードベースのアーキテクチャ劣化を完全に防ぎます。

---

## 60秒でわかる概要

| 項目 | 説明 |
| :--- | :--- |
| **概要** | 規約と軽量チェッカーの組み合わせ。全ソースファイルが先頭行で5つの正規ゾーン（`DOMAIN`, `CORE`, `INFRASTRUCTURE`, `PLUMBING`, `UI`）のいずれかを宣言します。 |
| **理由** | アーキテクチャは静かにドリフトし、AI エージェントはそのドリフトを加速させます。構造を機械検証可能なデータにすることで、大規模なリライトではなくコミットの段階で腐敗を阻止します。 |
| **方法** | 各ファイルを該当ゾーンのディレクトリに配置し、許容された方向へのみインポートを行い、`node bin/joy-check.mjs .` を実行します。終了コード `0` は完全な健全性を意味します。 |
| **コスト** | **外部依存ゼロ**、アカウント不要、ネットワーク不要、デフォルトで完全な読み取り専用。 |

### レストランの例え

コードベースをレストランとして想像してください：
- **厨房 (`DOMAIN`)**: 純粋な料理のレシピとビジネスルール。調理中にサプライヤーへ直接電話することは厳禁です。
- **配膳・統括 (`CORE`)**: オーダーの進行やユースケースのオーケストレーション。
- **調達・業者 (`INFRASTRUCTURE`)**: ファイルシステム、HTTP、DB などの I/O アダプタ。
- **フロア・客席 (`UI`)**: 顧客の意図を受け取り、画面を描画。食材パントリーに直接侵入してはなりません。
- **配管設備 (`PLUMBING`)**: 完全にステートレスな汎用ユーティリティ。他のゾーンに依存しません。

---

## 5つの正規ゾーン

| ゾーン | ディレクトリ | 責務と所有権 | ハード不変条件 |
| :--- | :--- | :--- | :--- |
| `DOMAIN` | `src/domain/` | ビジネスルール、エンティティ、契約 (`I*`) | **0% I/O**; インフラや UI のインポート厳禁 |
| `CORE` | `src/core/` | ユースケース統括、ステートマシン | UI のインポート禁止; インフラへは契約経由 |
| `INFRASTRUCTURE` | `src/infrastructure/` | fs, http, DB アダプタ | UI のインポート禁止; Domain の契約を実装 |
| `PLUMBING` | `src/plumbing/` | ステートレス関数、暗号、パス操作 | リーフ層; 他ゾーンのインポート禁止 |
| `UI` | `src/ui/` | CLI 出力、HTTP ルート、フロントエンド | インフラの直接インポート禁止 |

## クイックスタート（2分）

npm インストールは不要です（Node.js 18+ と git のみ）：

```bash
git clone https://github.com/CardSorting/HEAV3NS-JOY.git
cd HEAV3NS-JOY

# 1. テストスイートの実行 (196 tests passed)
npm test

# 2. アーキテクチャ監査の実行
npm run joy-check

# 3. エージェント設定の自動セットアップ (Claude, Cursor, Antigravity など)
npx heav3ns-joy init
```

詳細は [ドキュメントポータル](../README.md) および [仕様書](../../spec/00-CANONICAL-MODEL.md) をご覧ください。
