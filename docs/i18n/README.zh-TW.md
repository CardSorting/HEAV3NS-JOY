# HEAV3NS-JOY：架構主權與結構熵控制框架

[English](../../README.md) · [其他語言](README.md) · [入門指南](../GETTING_STARTED.md) · [Agent 協議](../../AGENTS.md)

> *「不要建造另一個讓智慧體運行的場所。建造可以讓智慧體學習、帶走並在任何地方獨立復現的事物。」*

**一句話總結：** HEAV3NS-JOY 透過極簡約定與零依賴檢查器，防止程式碼庫（無論是人類編寫還是 AI 智慧體生成）發生架構漂移。

---

## 60 秒核心概念

| 維度 | 說明 |
| :--- | :--- |
| **是什麼** | 一個極簡約定加上一個零依賴靜態分析工具。每個檔案在首行聲明所屬的五個規範區域之一（`DOMAIN`、`CORE`、`INFRASTRUCTURE`、`PLUMBING`、`UI`）。 |
| **為什麼** | 架構往往在無聲中漂移，而 AI 編碼智慧體會加速這種漂移。將架構轉化為機器可驗證的數據，在提交時就能阻止腐化，而不是等到全面重構。 |
| **怎麼做** | 將檔案放置在對應區域的實體目錄中，嚴格遵循單向依賴流，執行 `node bin/joy-check.mjs .`。結束碼 `0` 即為架構健全。 |
| **成本** | **零外部依賴**、無需註冊帳號、無需聯網、預設完全唯讀。 |

### 餐廳比喻

將程式碼庫想像成一家餐廳：
- **廚房 (`DOMAIN`)**：製作純正菜品與業務規則，嚴禁在烹飪中途直接給供應商打電話。
- **排程台 (`CORE`)**：協調出餐流程與使用案例排程。
- **供應商適配器 (`INFRASTRUCTURE`)**：負責食材採購、網路與資料庫 I/O。
- **餐廳大堂 (`UI`)**：接待顧客與渲染介面，絕不能直接走入食材倉庫。
- **後勤水電管線 (`PLUMBING`)**：純函式通用工具，完全無狀態且不依賴任何區域。

## 五大規範區域

| 區域 | 實體目錄 | 職責所有權 | 硬性規則 |
| :--- | :--- | :--- | :--- |
| `DOMAIN` | `src/domain/` | 業務規則、實體、值物件、`I*` 正式契約 | **0% I/O 熵**；嚴禁導入基礎設施或 UI |
| `CORE` | `src/core/` | 使用案例編排、狀態機、策略控制器 | 嚴禁導入 UI；透過介面與基礎設施互動 |
| `INFRASTRUCTURE` | `src/infrastructure/` | 檔案系統、HTTP、資料庫與第三方適配器 | 嚴禁導入 UI；必須實現 Domain 定義的介面 |
| `PLUMBING` | `src/plumbing/` | 無狀態通用工具、加解密演算法、路徑工具 | 葉節點依賴層；嚴禁導入任何其他區域 |
| `UI` | `src/ui/` | 控制台輸出、HTTP 路由、Web 頁面呈現 | 擷取使用者意圖；嚴禁直接導入基礎設施 |

## 快速上手（2 分鐘）

執行無需安裝任何 npm 依賴，只需 Node.js 18+ 與 git：

```bash
git clone https://github.com/CardSorting/HEAV3NS-JOY.git
cd HEAV3NS-JOY

# 1. 執行自測套件（196 個測試全部通過）
npm test

# 2. 執行架構主權審計
npm run joy-check

# 3. 為你的專案安裝 Agent 支援（Claude、Cursor、Antigravity 等）
npx heav3ns-joy init
```

完整文件請參閱 [文件中心](../README.md) 與 [規範標準](../../spec/00-CANONICAL-MODEL.md)。
